## 완료된 단계

- 프로젝트 골격: Spring Boot 4.1.0 / Java 21 애플리케이션 초기 생성, `DpgbApplicationTests` smoke test 존재.
- API 계약 정규화: `docs/api/openapi.yaml` 및 ADR-0001(`docs/api/decisions/0001-contract-normalization.md`) 수립.
- 개발 하네스 전환: 기존 `.kiro/steering` 산출물을 삭제하고 `AGENTS.md` + `.harness/*` 체계로 통합. DB는 PostgreSQL 단일 기준으로 확정, H2 제거 결정.
- API 계약 보완(CLIAR-10): `docs/api/openapi.yaml`에서 대응 필드 없는 `coverColors` 필터 제거, `language`/`coverUrl`/`bookNumber` 스키마 불일치 수정(ADR-0002). `docs/api/README.md`의 삭제된 `.kiro/steering` 문서 참조를 `AGENTS.md`/`.harness/ARCHITECTURE.md`로 정리. 오늘의 기분 추천은 범위 밖으로 확인. **(스크랩 범위 판단과 `language` 필드는 CLIAR-43(ADR-0003)에서 뒤집혔다 — 아래 참조.)**
- API 계약 재정의(CLIAR-43, ADR-0003): 담당 범위를 "단순 DB CRUD로 해결 가능한 부분"으로 재확인해 `docs/api/openapi.yaml`을 재작성했다. 장르(`genre`)·무드(`moodTags`)·`language` 필드와 관련 필터를 전 스키마에서 제거(알라딘 API가 언어 정보를 전혀 제공하지 않고 기능표에도 없어 함께 제거), 표지 OCR(`/books/ocr`)·AI 도서 분석(`/books/ai-analyze`) 엔드포인트 삭제(다른 MSA 컴포넌트 담당으로 확인), 외부 도서 검색을 알라딘 API 단일 소스로 한정(`ExternalBook`에서 `source`/`kdc`/`externalBookId` 제거, `author`는 알라딘의 역할 라벨 결합 문자열에서 이름만 정리해 반환, `totalPages`는 대부분 응답에 없어 선택 필드로 명시). `GET /api/v1/library/books`의 `sortBy`에 `PROGRESS` 추가, 필터는 `author`/`readingStatus`만 유지. 신규 리소스 2종 추가: 스크랩(Scrap, 책별 CRUD — 문장/페이지번호/메모), 동물 사서(Librarian 마스터 + 회원별 대표 사서 선택). 표지 이미지 교체(`replaceLibraryBookCover`)와 스크랩 이미지 교체(`replaceScrapImage`)는 한 차례 추가했다가, 둘 다 오브젝트 스토리지(S3) 연동이 필요해 "단순 DB CRUD" 범위를 벗어난다는 사용자 확인을 거쳐 계약에서 제거했다(스크랩의 `imageUrl` 필드도 함께 제거). 스크랩을 범위에 포함한 것과 `language` 제거는 각각 ADR-0002의 기존 결정("문장 OCR·감상·비밀 메모는 범위 밖", "language는 서버가 ko로 채운다")을 반전한 것 — 사유는 ADR-0003에 기록. `.harness/DOMAIN.md`에 Scrap/Librarian aggregate 규칙 추가, LibraryBook에서 `genre`/`moodTags`/`language` 제거. 도메인/영속성/컨트롤러 구현은 아직 시작하지 않았다 — `.harness/PLAN.md` 참조.
- 구현 계획 수립: 인증 기반 → 공통 계약 인프라 → LibraryBook 도메인/영속성 → Library CRUD → Reading Progress → Book Discovery(어댑터+스텁) → 계약 테스트 전수화 순서를 `.harness/PLAN.md`에 확정. 업무 규칙 문서 `.harness/DOMAIN.md` 신설(삭제된 `.kiro/steering/domain.md` 내용을 이 저장소 범위로 재정리), `CLAUDE.md` 단일 소유권 표에 반영.
- PostgreSQL 전환 + Gradle `integrationTest` 태스크 구성(CLIAR-26): `build.gradle`에서 H2 제거, `org.postgresql:postgresql`/Flyway(`flyway-core`, `flyway-database-postgresql`)/Testcontainers(`org.testcontainers:junit-jupiter`, `org.testcontainers:postgresql` 1.21.3 고정 — Spring Boot 4.1.0 BOM이 가리키는 2.0.5가 아직 Maven Central 미게시) 추가. `application.yaml`(공통) + `application-local.yaml`(Docker Postgres 기본값) + `application-prod.yaml`(env var, 기본값 없음) 프로필 분리, `spring.jpa.hibernate.ddl-auto: validate` + Flyway 활성화, 최초 baseline `db/migration/V1__init.sql`(빈 마이그레이션) 추가. 로컬 Postgres용 `docker-compose.yml` 신설. `integrationTest` source set/task를 새로 구성하고 `check`에 연결, `TestcontainersConfiguration`(`@ServiceConnection` + `withReuse(true)`)과 `IntegrationTestSupport`(`@SpringBootTest`) 기반 클래스를 `src/integrationTest`에 신설, 기존 `DpgbApplicationTests`를 `src/test`에서 `src/integrationTest`로 옮겨 `IntegrationTestSupport`를 상속하도록 전환(더 이상 DB 없이 컨텍스트가 뜰 수 없으므로). `./gradlew test`, `./gradlew integrationTest`(Docker Desktop 기동 후 실제 컨테이너로 검증 완료), `./gradlew check` 모두 통과 확인. `RepositoryIntegrationTestSupport`(`@DataJpaTest`)는 첫 Repository 테스트 작성 시점까지 보류.
- 공통 계약 인프라(CLIAR-29): `com.chc.dpgb.common.exception`에 `DomainException`(최상위) → status별 abstract 5종(`BadRequestException`/`ForbiddenException`/`NotFoundException`/`ConflictException`/`BadGatewayException`) → `openapi.yaml`의 stable error code별 concrete 예외 13종(2단 계층). `GlobalExceptionHandler`(`@RestControllerAdvice`)가 5개 abstract 타입 + 예기치 못한 예외(500, `INTERNAL_ERROR`)를 `ErrorResponse{code, message}`로 매핑. 401은 기존 `JwtAuthenticationEntryPoint`가 그대로 전담(범위 밖). `GlobalExceptionHandlerTest`(`@WebMvcTest`, `SecurityConfigTest` 패턴 재사용)로 6개 status 매핑 검증, `./gradlew test` 통과 확인. concrete 예외는 아직 도메인 패키지가 없어 우선 `common.exception`에 배치 — LibraryBook/Scrap/Librarian aggregate 구현 시점에 도메인 패키지로 옮길지 재검토.
- 인증 기반(CLIAR-28): AWS Cognito User Pool을 대상으로 Spring Security Resource Server(JWT) 구성. `com.chc.dpgb.security.SecurityConfig`가 `issuer-uri`(`AUTH_ISSUER_URI` env var, 기본값 없음) 기반 `JwtDecoder`, 전 endpoint 인증 필수 `SecurityFilterChain`, `AuthenticationEntryPoint` 빈을 한 곳에서 구성. Cognito Access Token에 `aud`가 없어 `com.chc.dpgb.security.jwt.TokenUseValidator`(`token_use==access`)와 `ClientIdValidator`(`client_id`가 `AUTH_APP_CLIENT_ID`와 일치)로 표준 audience 검증을 대체. `com.chc.dpgb.security.MemberIdResolver`가 `sub` 클레임을 memberId로 추출하는 단일 지점. 인증 실패(401)는 `com.chc.dpgb.security.JwtAuthenticationEntryPoint`가 `com.chc.dpgb.common.ErrorResponse{code: UNAUTHORIZED}`로 통일 응답. `JwtDecoder` 빈과 그 주입 지점을 모두 `@Lazy`로 표시해, 실제 Cognito User Pool 없이도(`AUTH_ISSUER_URI` 미설정) 앱 컨텍스트가 정상 기동하도록 함(첫 인증 요청 시점까지 discovery 네트워크 호출 지연) — `./gradlew integrationTest`로 이 상태에서 컨텍스트 기동을 실제로 확인. 단위 테스트(`TokenUseValidatorTest`/`ClientIdValidatorTest`/`MemberIdResolverTest`)와 `SecurityConfigTest`(`@WebMvcTest` + 테스트 전용 컨트롤러, `JwtDecoder`는 `@MockitoBean`)로 401/200 경로 검증. 실제 Cognito 토큰으로의 검증(decoder-validator 실동작)은 User Pool이 준비된 뒤 재검토 필요 — `.harness/BACKLOG.md`로 옮길 것.
- 서재 순서 필드 재설계(ADR-0004): 정수 `bookNumber`가 재정렬 시 전체 재번호가 필요하고 목록 조회에 전혀 반영되지 않던 문제를 확인해, LexoRank 방식의 불투명 문자열 `shelfRank`로 교체(`docs/api/openapi.yaml` v0.3.0). 순서 변경을 `updateLibraryBook`에서 분리해 전용 `PATCH /api/v1/library/books/{bookId}/order`(`reorderLibraryBook`, `beforeBookId`/`afterBookId` 이웃 지정)를 신설. `GET /api/v1/library/books`의 `sortBy` 기본값을 `SHELF_ORDER`로, `sortOrder` 기본값을 `ASC`로 변경하고 `LibraryBookSummary`에 `shelfRank` 노출 추가. `.harness/DOMAIN.md`에 `shelfRank` 규칙(유일성 제약, 삽입·rebalance 방식) 반영, `.harness/PLAN.md`(LibraryBook 도메인/영속성, Library CRUD API)에 구현 체크리스트 반영. 도메인/영속성/컨트롤러 구현은 아직 시작하지 않았다.
- `ReadingStatus` 제거(ADR-0005): CLIAR-31(LibraryBook 도메인/영속성) 구현 착수 시점에 사용자가 상태 필드 자체가 불필요하다고 확정. `docs/api/openapi.yaml`(v0.4.0)에서 `ReadingStatus` 스키마, `getLibraryBooks`의 `readingStatus` 필터, `UpdateReadingProgressResponse.readingStatus`를 제거하고 진도율(`progress`)만 남김. `.harness/DOMAIN.md`의 "페이지와 독서 상태" 절을 "페이지와 진도율"로 재정리(상태 매핑 규칙 삭제), `.harness/PLAN.md`(LibraryBook 도메인/영속성, Library CRUD API, Reading Progress API)에서 관련 체크리스트 문구 정리. 코드 구현 전 결정이라 별도 리팩터링 없이 처음부터 `ReadingStatus` 없이 설계한다.
- LibraryBook 도메인/영속성(CLIAR-31): `com.chc.dpgb.library` 패키지 신설. `LibraryBook`(JPA entity, aggregate root)이 `register`/`updateMetadata`/`updateProgress`/`changeShelfRank`에 불변식을 캡슐화(`totalPages>0`, `0<=currentPage<=totalPages`, 전체 페이지를 기존 현재 페이지보다 작게 줄이는 것 금지, 이전 페이지 정정 허용) — 위반 시 `IllegalArgumentException`(공통 `common.exception` 타입으로의 번역은 controller/service가 생기는 "Library CRUD API" 티켓에서 결정). `ShelfRank`는 Spring 비의존 LexoRank pure 유틸(`[0-9A-Za-z]` 62자, `initial`/`before`/`after`/`between`/`rebalancedSequence`) — 두 이웃 사이 공간이 128자를 넘어서게 되면 `ShelfRankExhaustedException`(내부 신호)을 던짐. 영속성은 포트/어댑터로 분리 — `LibraryBookRepository`(순수 인터페이스, Spring Data 비의존, 서비스 계층이 의존하는 도메인 메서드명: `save`/`findOwnedBook`/`findShelfOrderedByRank`/`findLastRanked`/`existsByIsbn`)와 `LibraryBookRepositoryJpaAdapter`(`@Repository`, package-private `LibraryBookJpaRepository`의 파생 쿼리 메서드로 위임)로 나눠, 서비스 계층이 JPA 쿼리 메서드명에 직접 결합되지 않게 했다. `LibraryBookJpaRepository`를 어댑터 클래스 내부 nested interface로 옮기는 것도 시도했으나 Spring Data JPA가 nested interface를 리포지토리 빈으로 스캔하지 못해(`NoSuchBeanDefinitionException` 실증) 되돌렸다 — package-private 최상위 인터페이스로 동일한 캡슐화 목표를 달성. `LibraryBook`의 getter는 Lombok `@Getter`로 생성(setter 없음, 상태 변경은 도메인 메서드로만). Flyway `V2__create_library_book.sql`로 `library_book` 테이블과 unique 제약(`member_id`+`shelf_rank`, `member_id`+`isbn` partial — isbn 있는 도서만, ADR-0007) 추가. `RepositoryIntegrationTestSupport`(`@DataJpaTest`+Testcontainers, 이 저장소 최초 사용)를 `ARCHITECTURE.md` 설계대로 신설하고 `LibraryBookRepositoryTest`(8개, unique 제약 위반 포함)로 검증. 단위 테스트 `ShelfRankTest`(10개)/`LibraryBookTest`(14개) 포함 `./gradlew check` 전체 통과 확인. 이 작업 중 `spring-boot-starter-flyway` 누락(CLIAR-26부터 Flyway가 실제로 한 번도 자동 실행되지 않던 결함)을 발견해 함께 수정 — 상세는 `.harness/DECISIONS.md` 참조. controller/service 배선과 `shelfRank` rebalance 오케스트레이션은 "Library CRUD API"로 이연.
- `updateLibraryBook`을 전체 필드 포함 방식으로 통일(ADR-0006): `UpdateLibraryBookRequest`(`docs/api/openapi.yaml` v0.5.0)가 7개 필드를 모두 `required`로 요구하도록 바뀌었다 — `isbn`/`publisher`/`publishedDate`/`coverUrl`는 `null`=삭제, `title`/`author`/`totalPages`는 `null` 불가(`Scrap.updateScrap`과 동일 규칙). `LibraryBook.updateMetadata(...)`(도메인 메서드)도 같은 규칙으로 맞춰 부분 수정(null-스킵) 로직을 제거했다. `.harness/DOMAIN.md`(LibraryBook aggregate 절에 규칙 추가), `.harness/PLAN.md`(Library CRUD API 체크리스트 문구 갱신) 반영, `LibraryBookTest`에 관련 테스트 4개 추가(총 14개).
- ISBN 없는 도서의 제목·저자 중복 판정 제거(ADR-0007): 서로 다른 책이어도 제목·저자가 우연히 같을 수 있어 서버가 강제하지 않기로 확정. `LibraryBook`에서 `normalizedTitle`/`normalizedAuthor` 필드·정규화 로직 제거, `LibraryBookRepository`/`LibraryBookJpaRepository`/`LibraryBookRepositoryJpaAdapter`에서 `existsBy...NormalizedTitleAndNormalizedAuthor` 계열 메서드 제거, `V2__create_library_book.sql`에서 해당 컬럼·unique 인덱스 제거(아직 배포 전이라 별도 마이그레이션 없이 V2 직접 수정). ISBN 있는 도서의 유일성 판정만 남는다. `docs/api/openapi.yaml`은 이 메커니즘을 wire 계약에 노출한 적이 없어 스키마 변경은 없음(ISBN 없이 재등록 시 409→201로 바뀌는 동작 변화만 있음). `LibraryBookRepositoryTest`에서 관련 테스트 1개 제거(9→8개), `./gradlew check` 재통과 확인.
- 책장(Shelf) 관리 API 계약 설계(ADR-0008): 사용자가 제시한 기능표(책장 생성/책 넣기/수정/삭제/책장별 목록 조회/책장 목록 조회)를 바탕으로 `docs/api/openapi.yaml`(v0.6.0)에 `Shelf` 태그와 신규 endpoint 5개(`createShelf`/`getShelves`/`updateShelf`/`deleteShelf`/`getShelfBooks`) + `moveLibraryBookToShelf`(책 이동)를 추가했다. 핵심 설계 결정은 `shelfRank`(ADR-0004)의 유일성 범위를 사용자 전역(`memberId`)에서 책장별(`shelfId`)로 좁힌 것 — "책장별 책 목록 조회"가 그 책장 안의 진열 순서를 보여줘야 자연스럽기 때문이며, 사용자에게 `AskUserQuestion`으로 확인받았다(범위 축소/기본 책장 get-or-create 자동 생성/기본 책장 이름 변경 허용, 셋 다 권장안 그대로 확정). `reorderLibraryBook`은 같은 책장 내 이웃만 허용하도록 설명을 보강했고, 책장 간 이동은 별도 endpoint로 분리했다. `CreateLibraryBookRequest`에 선택적 `shelfId`, `CreateLibraryBookResponse`/`LibraryBookSummary`/`LibraryBookDetailResponse`에 `shelfId` 노출, `getLibraryBooks`에 선택적 `shelfId` 필터(하위 호환 위해 생략 시 전체 책장 합산 유지)를 추가했다. `.harness/DOMAIN.md`에 `Shelf` aggregate 절 신설, `LibraryBook`/`shelfRank` 절을 책장 범위로 갱신, `docs/api/decisions/0008-shelf-management.md`(ADR-0008) 신설, `docs/api/README.md` ADR 목록 갱신. 스크립트로 `$ref` 무결성·중복 `operationId`·미사용 스키마/응답/파라미터 검증 완료(operationId 22개). 이 단계는 계약 수준 설계만 다뤘다 — 구현은 아래 "Library CRUD API + 책장(Shelf) 관리(CLIAR-32)" 참조.
- Library CRUD API + 책장(Shelf) 관리 구현(CLIAR-32): ADR-0008 계약을 실제 코드로 구현했다. `Shelf` aggregate(`create`/`rename`, `isDefault`는 서버 전용) + `ShelfRepository`(포트)/`ShelfJpaRepository`/`ShelfRepositoryJpaAdapter`(`LibraryBookRepository`와 동일 패턴), `ShelfService`(`getOrCreateDefaultShelf` — `(member_id) WHERE is_default` 부분 unique 인덱스로 동시성 보장, 위반 시 재조회, `createShelf`/`getShelves`/`updateShelf`/`deleteShelf`(내부 책을 기본 책장 맨 뒤로 이동 후 삭제)/`getOwnedShelf`(404→403 순서)). `LibraryBook`에 `shelfId` 필드와 `changeShelfId` 추가, `register()` 시그니처에 `shelfId` 반영. `V3__add_shelf_and_rescope_library_book.sql`로 `shelf` 테이블 신설, `library_book.shelf_id`(+FK) 추가, 기존 데이터 백필, `shelfRank` unique 제약을 `member_id` 전역→`shelf_id` 범위로 재조정(`V2`는 이미 `develop`에 병합돼 직접 수정하지 않고 새 마이그레이션으로 처리). `LibraryBookRepository`(포트)를 `findOwnedBook`(소유자 스코프 단일 조회) 대신 스코프 없는 `findById` + 서비스 계층의 명시적 소유자 비교로 교체했다 — 계약의 모든 관련 endpoint가 403(권한 없음)과 404(없음)를 별도 응답으로 구분하는데 `findOwnedBook`으로는 이 둘을 구분할 수 없었기 때문(설계 시점에 발견). 페이징/필터/정렬(`findPage`, `findPageOrderByProgress`)은 Querydsl 없이 Spring Data JPA `@Query` + `Pageable`의 `Sort` 자동 결합으로 처리하고, 저장 컬럼이 아닌 `PROGRESS` 정렬만 계산식 `ORDER BY`를 쓰는 전용 쿼리로 분리했다. `LibraryBookService`가 CRUD/`reorderLibraryBook`(이웃 탐색 후 `ShelfRank.between`, `ShelfRankExhaustedException` 시 `rebalancedSequence`로 재계산 후 재시도)/`moveLibraryBookToShelf`/`updateReadingProgress`를 구현하고, 도메인의 `IllegalArgumentException`을 각 상황에 맞는 `common.exception` 타입으로 번역한다. 신규 concrete 예외 6종(`InvalidReorderTargetException` — ADR-0004 이후 endpoint라 CLIAR-29 때 누락됐던 것을 이번에 발견해 추가, `InvalidShelfTargetException`/`InvalidShelfDataException`/`ShelfAccessDeniedException`/`ShelfNotFoundException`/`DefaultShelfCannotBeDeletedException`). `LibraryBookController`/`ShelfController`(`com.chc.dpgb.library.web`)가 `@AuthenticationPrincipal Jwt` + `MemberIdResolver`로 memberId를 얻는 기존 컨벤션을 따른다. DTO는 Bean Validation 없이 `openapi.yaml` 스키마 1:1 대응 record로만 구성했다 — 도메인 계층이 이미 필수/불변식을 검증하므로 서비스가 그 예외를 번역하는 방식으로 통일하고, 컨트롤러는 primitive 언박싱이 필요한 필드(totalPages/currentPage)의 null만 직접 체크한다. `getLibraryBooks`의 `author` 필터는 정확히 일치로, `createLibraryBook`에 잘못된/남의 `shelfId`를 보낸 경우는 계약에 전용 응답이 없어 기존 400(`INVALID_BOOK_DATA`)으로 처리하기로 사용자에게 확인받았다. 검증: `ShelfServiceTest`/`LibraryBookServiceTest`(Mockito, get-or-create 동시성·소유권 404/403·reorder 검증/rebalance·중복 409 등), `LibraryBookControllerTest`/`ShelfControllerTest`(`@WebMvcTest`), `LibraryBookRepositoryTest`(shelf 범위로 갱신)·`ShelfRepositoryTest`(신규) 포함 `./gradlew check`(Docker Desktop 기동, 실제 PostgreSQL) 전체 통과.
